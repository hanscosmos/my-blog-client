## 关键发现与分析

### ⚠️ 用户的前提假设不成立（重要）

用户最初提到「消息提醒后台管理系统是有的」。实际核查后确认：

- `my-blog-admin` 里**没有评论管理**，`MessageBtn` 是纯占位（`<script setup>` 空，无点击处理器、无 API）
- 后端**没有评论模型，也没有消息提醒模型**
- 后端**根本没有注册接口**——`/user/add` 是管理端接口（需 JWT + 权限码），前台不存在注册入口

因此「登录后才能评论」这个前提，在没有注册入口的情况下只能靠后台加用户。已如实反馈给用户，未按错误假设规划。

### 数据模型：一张表承载所有评论类型

用 `targetType` + `targetId` 区分评论对象（文章 / 留言板 / 未来的随笔），避免每加一种类型就建一张表。

### 两级结构 + 扁平回复

- 顶层评论 `rootId` 为空，按 `createTime` **倒序**（最新在前）
- 回复统一挂在所属顶层评论下，**扁平存储**（不嵌套树），按 `createTime` **正序**（最早在前）
- 「A 回复 B」由 `replyUser` 表达，只在回复时写入

### 权限判定放在服务端

`canDelete` 由后端逐条算好返回，前端**不需要知道当前用户是不是博主**，也就不会出现前后端权限口径漂移。`can_delete_comment`（作者本人 或 内容作者）被 `list` 与 `delete` 共用。

### 刻意绕开项目既有的序列化范式

项目的 `ArticleSerializers` 用 `ModelSerializer.to_representation`，每条都要额外查分类/父分类/作者/标签，N+1 严重。评论列表**没有沿用**，改为手写 `format_*` 函数 + `build_user_map` 批量查用户，整个列表固定 4 条 SQL（顶层分页 / 回复 / 用户 / 回复数）。

### `limit_queryset` 的 `total` 不可用

`utils/tools.limit_queryset` 在页码越界时返回 `{'result': [], 'total': 0}`。前端的空页回退逻辑依赖准确的 `total`，因此列表视图**自己算** `root_total = root_sql.count()`，不用它的 `total`。

| 2 | 别人回复了我的评论后，我无法回复别人的评论，提示「不能回复自己的评论」 | ✅ **真 bug**。见下 |
| 3 | 发表按钮挡住 `0/500` 字数 | ✅ antd `showCount` 绝对定位在右下角，与右对齐按钮必然重叠。去掉 `showCount`（保留 `maxLength`），改为自己在 `flex-between` 行里渲染计数（左计数、右按钮） |

### 问题 2 的根因

原判断拿的是**顶层评论的作者**与当前用户比，而不是**被回复的人**：

```python
# 错误：root.user 是楼层主人，不是被回复者
if str(root.user) == str(user_id):
    return res_handle(501, '不能回复自己的评论', None)
```

结果：只要有人回复过我的评论，那条评论所在的整个楼层就对我永久锁死。修正为判断被回复者：

```python
if str(reply_user) == str(user_id):
    return res_handle(501, '不能回复自己的评论', None)
```

**语义边界**：「不能回复自己」拦的是回复对象是自己，而不是「不能在别人回复了自己的楼层里继续回复」。后者 `replyUser` 是别人，必须放行。

## 后续注意事项

### 遗留项

1. **富文本评论**（表情 / 图片）——用户明确「后面再改」。`src/ai/plan/comment.md` 已列 5 个待定点：编辑器与表情选型、`content` 改 `TextField` 且**必须做 XSS 过滤**（否则是存储型 XSS）、图片走 `resource` 模块上传并考虑引用计数、长度校验语义变更、与历史纯文本数据的兼容
2. **消息提醒**未做
3. **前台注册入口**未做（用户明确本次跳过）
4. **评论审核**：当前 `status` 默认 `visible`，是「先发后审」；后台无评论管理界面，被隐藏的评论目前没有操作入口

### 设计要点（改动时别踩）

- 顶层评论删除会**连带软删其下所有回复**（`rootId=该评论id` 全部 `isDelete=True`）
- 前端提交回复时**不整页重拉**，而是按 `res.rootId` 就地追加；提交顶层评论时回第 1 页重拉（最新在前）
- 空页回退：删掉某页最后一条后该页为空，`fetchList` 检测 `result.length === 0 && total > 0 && page > 1` 则退一页；空状态判定用 `total === 0` 而非 `list.length === 0`
- `comment.d.ts` 的 `CommentReplyItemType` 带 `rootId`，回复「回复」时靠它定位楼层
